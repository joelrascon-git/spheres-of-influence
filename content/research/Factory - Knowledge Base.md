# Factory (Factory AI) Knowledge Base for Enterprise Sales Agents
*Last verified: October 12, 2026. Factory uses both factory.com (current primary) and factory.ai (legacy, still live). Labels used: **[Vendor]** = Factory's own claim; **[Customer]** = customer-attributed, published by Factory; **[Independent]** = third party; **[Unverified]** = single secondary source.*

Factory is a San Francisco company, founded in 2023, that sells a model-agnostic, deploy-anywhere platform of autonomous coding agents ("Droids") that its leaders now position as an enterprise "software factory," automating the whole SDLC rather than just code completion ([Factory 2.0](https://factory.com/news/software-factory)). Sell it as a platform and governance decision for engineering leadership, not as a developer seat tool.

## TL;DR
- **What it is:** Droids run in the terminal (CLI), the Desktop App, IDEs, Slack/Linear/Jira, and CI. Factory adds Missions (multi-agent orchestration of long projects), Automations, model routing, Analytics, and SaaS/hybrid/on-prem/air-gapped deployment. Factory raised $200M at a $5B valuation on September 15, 2026 ([Factory](https://factory.com/news/5-billion-valuation)).
- **Where it wins:** Large, regulated enterprises with legacy estates, multi-model or sovereignty requirements, and bounded modernization or migration programs. The strongest proof is Comarch: an XSLT modernization estimated at 10,000 person-days finished in 45 days ([Comarch case study](https://factory.com/case-studies/comarch)).
- **Where it loses:** Buyers who want IDE autocomplete, teams without review capacity or test automation, and shops already standardized on a single first-party agent such as Claude Code or Codex ([Continuum review](https://continuumcode.ai/guides/factory-ai-review/)). Most of the performance evidence is vendor-published.

**Glossary**
- **Droid:** Factory's agent. One harness that runs across interfaces and models.
- **Custom Droids:** user-defined subagents with their own model, tools, and MCP servers ([MCP docs](https://docs.factory.com/harness/mcp)).
- **Missions:** structured, multi-feature orchestration. You plan with Droid, then Mission Control runs workers and validators ([Missions docs](https://docs.factory.com/missions/overview)).
- **Mission Control / Mission Mode:** the orchestration view, and the session state you enter after approving a mission plan ([Missions docs](https://docs.factory.com/missions/overview)).
- **Specification Mode:** Droid inspects the repo and proposes a plan with acceptance criteria, file-level changes, and tests before editing ([Continuum review](https://continuumcode.ai/guides/factory-ai-review/)).
- **Autonomy levels:** Manual, Low, Medium, High. Organization policy and deny lists constrain them ([Continuum review](https://continuumcode.ai/guides/factory-ai-review/)).
- **Agent Readiness:** a repo maturity score (`/readiness-report`, `/readiness-fix`). Missions recommend Level 4 (Optimized) or higher ([Missions docs](https://docs.factory.com/missions/overview)).
- **Droid Computers:** persistent cloud or BYO machines for background Droids ([Factory Desktop App](https://factory.com/news/factory-desktop)).
- **Droid Exec:** headless `droid exec` for scripts and CI ([Droid Exec docs](https://docs.factory.com/droid-exec/overview)).
- **Droid Core:** included open-weight models with a separate usage pool ([Continuum review](https://continuumcode.ai/guides/factory-ai-review/)).
- **Factory Router / Auto model:** task-based model routing ([Factory Router](https://factory.com/news/factory-router-inference-savings)).
- **Factory Standard Credits:** the consumption unit, computed from tokens with cache discounts ([Kunavo](https://kunavo.com/guides/factory-droid-pricing)).
- **Software Factory:** the App view that tracks SDLC-stage automations, coverage, and health ([Software Factory docs](https://docs.factory.com/software-factory/overview)).
- **Factory Private / Managed / FedRAMP:** the deployment models ([Factory Private](https://factory.com/news/factory-private)).
- **DroidShield:** generated-code security scanning ([Factory Security](https://factory.ai/security)).
- **FPN:** Factory Partner Network ([FPN post](https://factory.com/news/factory-partner-network)).

## 2. What Factory solves for
- **Coding is a minority of the SDLC.** In the August 19, 2026 FPN post, Factory's Mark Kobe argues that "even with frontier models, writing code is about 20% of the software development lifecycle." He cites Gartner's finding that teams applying AI across the full lifecycle see 25–30% productivity gains. In this framing, the bottleneck is deciding, designing, testing, securing, shipping, and monitoring ([FPN post](https://factory.com/news/factory-partner-network)).
- **Individual productivity has plateaued as a goal.** "Improving the productivity of individual engineers is no longer enough" ([Factory 2.0](https://factory.com/news/software-factory)).
- **Fragmented context.** Nav's code lived in on-prem GitLab, docs in Confluence, tickets in Jira, and discussions in Slack. Copilot sped up typing but not "everything around it" ([Nav case study](https://factory.com/case-studies/nav)).
- **Model lock-in and lab risk.** Factory pitches model-agnosticism as "insurance against relying on one AI lab" ([TechFundingNews](https://techfundingnews.com/factory-jumps-to-5b-in-5-months-with-200m-for-its-ai-droids/)).
- **Data sovereignty.** Code that cannot leave the perimeter gets VPC, on-prem, and air-gapped options ([Factory Private](https://factory.com/news/factory-private)).
- **Token cost.** Routing "can cut token costs by more than 50% at the same quality" [Vendor] ([FPN post](https://factory.com/news/factory-partner-network)).

### 3.2 Workflow capabilities
- **Missions.** Sweet spot is "about 1–500 features." Covers full-stack builds, research, brownfield migrations, and prototypes. Missions run user-facing QA to self-validate, so the repo needs scriptable app exercise. Factory lists open questions on parallelization, correctness, and cost ([Missions docs](https://docs.factory.com/missions/overview)). Missions draw on rolling limits and require Extra Usage to be enabled ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)).
- **Automations.** Generally available since September 30, 2026 ([News](https://factory.com/news?category=customers)). Templates:
  - Ticket-to-PR (every 15 minutes from Linear/Jira)
  - Code Health
  - Channel Q&A
  - Alert Responder (Sentry/Datadog/PagerDuty)
  - CI Failure Triage
  - New Issue Investigator
  - Docs Refresh
  - Code Review

  Source: [Automations docs](https://docs.factory.com/software-factory/automations).
- **Automated Code Review.** Runs on GitHub or GitLab, with model aliases checked against organization policy ([Code review docs](https://docs.factory.com/software-factory/code-review-ci)). **Automated Security Review** adds STRIDE-based findings with CWE references as inline PR comments ([Enterprise page](https://factory.ai/enterprise)).
- **Automated QA.** Browser-driven, "the way a real user would." Launched April 23, 2026 ([Product news](https://factory.com/news?category=product)).
- **Incident Response.** Launched July 10, 2026 ([News](https://factory.com/news#case-studies)). Set up with `/setup-incident-response` for Slack auto-run ([CLI reference](https://docs.factory.com/droid-cli/cli-reference)).
- **Context and memory.** Factory's "anchored iterative" compaction scored 3.70 vs Anthropic 3.44 and OpenAI 3.35 in a vendor-run December 2025 study [Vendor] ([Compaction article](https://factory.com/articles/coding-agent-context-compaction)). In customer use, Chainguard ran a two-week single session ([Chainguard](https://factory.com/case-studies/chainguard)).
- **Extensibility.** MCP with a 40+ server registry (Linear, Sentry, Notion, Stripe, Vercel), plus skills, hooks, plugins, and custom Droids. Enterprise MCP allowlist policy ([MCP docs](https://docs.factory.com/harness/mcp); [CLI reference](https://docs.factory.com/droid-cli/cli-reference)).

### 3.3 Models

## 6. Poor-fit use cases and known weaknesses
- **Autocomplete buyers.** "Weak" fit: "Droid owns tasks; it is not primarily a predictive typing product" ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)).
- **Teams without review capacity.** "Risky": autonomous output becomes review debt ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)).
- **Repos without automated tests or scriptable QA.** Missions "cannot reliably verify [their] own work" below Readiness Level 4 ([Missions docs](https://docs.factory.com/missions/overview)).
- **Open-ended goals.** "Improve the architecture" is a weak Mission. Missions need acceptance boundaries ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)).
- **Single-lab shops.** A "mixed" fit, because Factory adds a platform layer on top of an agent that may already work ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)).
- **Cost predictability.** Quotas are published as multipliers, not token amounts ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)). Users report heavy token burn and re-prompting ([eesel](https://www.eesel.ai/blog/factory-ai-alternatives)). In Every's October 30, 2025 "Vibe Check," Danny Aziz (GM of Spiral at Every) burned through the Max plan's 200M tokens in a week ([Every](https://every.to/vibe-check/vibe-check-i-canceled-two-ai-max-plans-for-factory-s-coding-agent-droid)).

## 11. Qualification playbook

**ICP:**
- 500+ engineers.
- Regulated industry (FS, healthcare, public sector, defense) or IP-sensitive.
- Legacy estate (monoliths, XSLT/COBOL, on-prem SCM).
- Uses multiple model providers, or has an AWS, Anthropic, or OpenAI commit.
- Has a CTO/CAIO AI mandate.
- Has CI with automated tests.

**Buying signals:**
- A public "X% of code by AI" target, like Comarch's 100% by end of 2026.
- A modernization or migration program with a person-day estimate.
- Several AI coding tools running in parallel that the org wants to consolidate (as at You.com).
- An unused model-lab commit.
- A sovereignty or air-gap requirement.
- New AI platform team or Chief AI Officer hires.
- A Wipro or EY relationship.

**Disqualifiers:**
- Wants autocomplete only.
- No test automation and no appetite for readiness work.
- Review capacity already saturated.
- Hard requirement for GA FedRAMP today.
- Committed to a single lab's bundled agent with no governance needs.
- Needs fixed, predictable per-seat spend with no usage variance.

**Objection handling:**
| Objection | Response |
|---|---|
| "We have Copilot/Cursor." | Nav kept Copilot and added Factory for everything around the code ([Nav](https://factory.com/case-studies/nav)). |
| "The labs will build this." | Model-agnosticism hedges lab risk, and Factory sells through the labs' own marketplaces. |
| "Costs are unpredictable." | Router (-63% [Vendor]), Analytics cost-per-outcome, and Droid Core. Pilot on a fixed task mix. |
| "Security." | Private/air-gapped deployment, ZDR, never trains on customer code, Trust Center. Confirm the SOC 2 type. |
| "Benchmarks are marketing." | Agree. Run a 15–30 task pilot with acceptance tests ([Continuum](https://continuumcode.ai/guides/factory-ai-review/)). |
